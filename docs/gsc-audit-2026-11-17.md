### Immutable caching with unchanged asset URLs

1. **The Issue:** Confirmed for FX2USD during additional live delivery checks after the first release. Production sends `Cache-Control: public, max-age=31536000, immutable` for `app.js`, `styles.css`, and `sw.js`, while the earlier build kept unchanged script and stylesheet URLs. The first release's fresh HTTP and file-hash verification missed the returning-browser path. Evidence is retained in `.cache/gsc-2026-11-17/asset-cache-headers.json`.
2. **The Impact:** A returning browser can reuse older script and style responses for a year, even after the server files change. That can prevent a user from receiving a correction or produce a mixture of new HTML and old application files. This is a delivery and user-experience defect, not evidence that Google deindexed the page.
3. **The Code-Level Solution:** Updated `scripts/build.js` to add SHA-256 content hashes to local asset URLs in generated HTML, to manifest icons and screenshots, and to the worker's matching precache list. A changed icon also changes the parent manifest URL. Source files still work locally without building, and the PWA id, start URL, and scope stay stable. Updated `app.js` to register the worker with `updateViaCache: "none"`, consistent with the [browser API contract](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/register). Four new build tests cover actual content hashes, manifest identity, script changes, icon dependency changes, and worker-request coherence. The full quality gate now passes 26 tests. Version `0.1.2` is prepared for the protected release workflow and canonical deployment. No shared root-host rule was changed. After upload, verify the live `?v=` URLs against package bytes and recheck the final mobile rendering sample. No second indexing request is needed solely for cache keys when the indexable content is unchanged.

### Shared-origin cache cleanup during the canonical upgrade

1. **The Issue:** Confirmed in `sw.js` while preparing the first canonical release of the current PWA. Activation deleted every cache other than the current FX2USD cache. The canonical host also serves sibling applications. The baseline canonical app had no service worker, so this was a prospective deployment regression rather than an observed indexing failure.
2. **The Impact:** Activating this release could discard sibling apps' cached files. This affects offline behavior and user experience, not direct indexability. Releasing the existing worker unchanged would violate the campaign's requirement to preserve other projects.
3. **The Code-Level Solution:** Restricted cleanup to names beginning with `fx2usd-app-v`, retaining unrelated caches. Updated `tests/sw.test.js` to keep a seeded sibling-app cache through installation and activation while removing the stale FX cache. The package and worker version are both `0.1.1`. The full quality gate passes with 22 tests. Deployment verification includes the worker file hash. No root or sibling cache code was changed.

They lacked a short visible explanation of rate direction, manual overrides, cached rates, and practical limitations. This bounded content gap is now corrected in the deployed release. It explains currency selection, the USD result, live and saved rates, manual USD-per-unit quotes, banknotes, and on-device history using behavior verified in `app.js`. No duplicate currency pages or speculative rating schema were added. The full quality gate passes. Post-release HTTPS confirms that the final section is present in the indexable document. Chrome rendering and live/manual conversion checks remain pending the shared browser lease. Measure query-by-page exposure over complete later periods before attributing any movement to this text.
