## Medium

### Canonical production publishing gap, recovered during this audit

1. **The Issue:** Confirmed for FX2USD. This repository is the source owner, but `.github/workflows/pages.yml` deploys only `https://tocatlian.github.io/fx2usd/`. GitHub's Pages configuration reports that mirror URL, no custom domain, and workflow deployment. Baseline source commit `b417bbe0e9f7e73696a94e7f74e5a563292df75c` matched the mirror's HTML. At baseline, the canonical Apache URL returned different HTML, JavaScript, CSS, and manifest. Its HTML Last-Modified was July 30, 2026. The canonical and mirror HTML SHA-256 values are `116faaee74125437f594943a0cb4f363ece9308816b817a673d85636744982cd` and `bbbada89da4dcb4944b22d198e106b90387b9622cddbe69364f84dd161c11a0d`, respectively. `docs/local-maintenance.md` already states that a HostGator command, connection configuration, and destination are missing. The root project reference explicitly leaves this app's publishing bridge unverified.
2. **The Impact:** A successful Pages release cannot demonstrate that a correction reaches the indexed URL. Production still uses external Google Fonts and predates current local accessibility, offline, and packaging improvements. This blocks a trustworthy canonical release and verification receipt. It does not establish a search ranking penalty or a current crawl-access failure.
3. **The Code-Level Solution:** Recovered through the existing trusted shared-host connection without changing account access. At November 17, 2026, 18:07:56 UTC, read-only SFTP confirmed `public_html/tocatlian.com/apps/fx`. Its downloaded HTML and JavaScript hashes matched both canonical HTTPS responses exactly. Added `scripts/deploy-hostgator.js`, the private app-scoped `.env.hostgator` configuration, a credential-free example, and documented plan/apply commands. The uploader requires a clean committed checkout, the full quality gate, the fixed target and exact ten-file runtime allowlist. It backs up the remote app subtree, checks its HTML against live HTTPS before upload, uploads assets before HTML, and verifies every published file over SFTP and HTTPS. Its private receipt and rollback batch preserve predecessor evidence. Regression tests reject root, sibling and traversal destinations and command injection. `README.md`, `PUBLISHING.md`, and `docs/local-maintenance.md` now distinguish the canonical release from Pages and keep recurring deployment disabled. Production release evidence will be appended after the authorized upload. The root sitemap lastmod update remains a root-project dependency after that release.

### Shared-origin cache cleanup during the canonical upgrade

1. **The Issue:** Confirmed in `sw.js` while preparing the first canonical release of the current PWA. Activation deleted every cache other than the current FX2USD cache. The canonical host also serves sibling applications. The baseline canonical app had no service worker, so this was a prospective deployment regression rather than an observed indexing failure.
2. **The Impact:** Activating this release could discard sibling apps' cached files. This affects offline behavior and user experience, not direct indexability. Releasing the existing worker unchanged would violate the campaign's requirement to preserve other projects.
3. **The Code-Level Solution:** Restricted cleanup to names beginning with `fx2usd-app-v`, retaining unrelated caches. Updated `tests/sw.test.js` to keep a seeded sibling-app cache through installation and activation while removing the stale FX cache. The package and worker version are both `0.1.1`. The full quality gate passes with 22 tests. Deployment verification includes the worker file hash. No root or sibling cache code was changed.

## Low

### Limited explanatory content for the converter

1. **The Issue:** Confirmed source observation for FX2USD, with unmeasured search impact. Both `index.html` and the canonical HTML mainly expose controls, results, banknotes, and history. They lack a short visible explanation of rate direction, manual overrides, cached rates, and practical limitations. Current disclosed search volume is insufficient to identify a specific missing query or substantiate a CTR opportunity.
2. **The Impact:** Concise instructions could help new visitors understand the app and give search systems useful visible context. No traffic gain or AI citation is established. Existing discovery is present through the root sitemap and the root site's coding-journey page, so the app is not a confirmed orphan.
3. **The Code-Level Solution:** Added a visible usage section in `index.html` after the app's history section. It explains currency selection, the USD result, live and saved rates, manual USD-per-unit quotes, banknotes, and on-device history using behavior verified in `app.js`. No duplicate currency pages or speculative rating schema were added. The full quality gate passes. The release must confirm the final rendered section and live/manual conversion behavior. Measure query-by-page exposure over complete later periods before attributing any movement to this text.
